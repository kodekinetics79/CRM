## Architecture and authority boundaries

The built evaluator serves React assets and authenticated Express API from one Node.js process on loopback. SQLite provides local persisted records. JSON record relationships are checked in synchronous application transactions; they are not all relational foreign-key constraints inside the JSON payloads. API input validation, reference checks, financial ceilings, write and audit run within `BEGIN IMMEDIATE`, so a failed batch/linked action cannot leave partial business writes.

Generic updates/deletes, gift voids, acknowledgments, clocks and corrections require current integer versions. Event membership operations and settings have transactional current-state validation without caller-version stale-intent rejection. Generic audit captures actor/action/record/time, not complete before-and-after field values; financial void reasons and time correction evidence are retained separately. Append-only audit triggers are a local application control, not privileged filesystem-tampering assurance.

Staff and administrator conduct ordinary business workflows. Administrator alone manages users/settings/audit/snapshots. Board reads business records and reports, exports feedback and submits observations; the feedback exception grants no business-edit authority. A task owner label is descriptive assignment, a soft credit is recognition, a constituent funder link is identity, and a typed tester name is a display label. None grants application privileges.

The client mental model is supported through specific actions and connected evidence: gift allocation opens its designation; donor history opens the gift; a grant opens its funder and linked receipt history; an acknowledgment opens its interaction; pledge history opens its receipts; volunteer intervals preserve original event linkage. Optional screen help explains the next action and value semantics at first glance. The independent scenario list allows clients to choose order and pace; it is not a forced tour. Dense/mobile priority layouts and shortcut behavior still require actual browser acceptance, because code inspection alone cannot establish usable focus or narrow-screen interaction.
