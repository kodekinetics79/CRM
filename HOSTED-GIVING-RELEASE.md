# Wimblo — hosted giving and financial evidence

September 13, 2026. Kode Kinetics LLC. Ninth local requirements-first release. This is source/test evidence, not an executed payment-provider account, district acceptance, production handover or predicted procurement score.

## What this release adds

An administrator can review an existing donor, active campaign and designation with exact USD cents, prepare a TEST_ONLY hosted checkout, inspect retained signed payment evidence, explicitly verify the expanded server-retrieved payment, and separately record one native gift after a fresh provider recheck. Preparation, return-page navigation, an unpaid completion and a signed callback alone do not record income. The UI guides each action with current-source versions, review reasons, safe external-link validation and retained outcome history.

Official Stripe SDK 22.6.2 is pinned with its shipped API version 2026-08-26.dahlia. Hosted Checkout Sessions use the current hosted_page interface. Test keys are server-only. The service rejects live mode, Connect/account routing, mismatched tenant/intent/source/session/payment identities, amount/currency drift and unsupported payment methods. A current expanded charge must show successful captured payment, no refund and no dispute; the supported method is card or us_bank_account. The original signed payment-evidence date is retained separately from verification time and bank settlement. No PAN/CVV, donor consent, tax receipt or bank settlement is inferred.

A required request UUID binds the exact reviewed request and native source snapshot. Exact repeated initial requests return the original retained intent without another provider call. Changed requests under that UUID fail. Unknown external outcomes retain the original key and parameters; an explicit retry is bounded to 20 hours, with no replacement key after expiry. The UI blocks blind replay and requires saved-history inspection before another preparation. Native recording uses fresh authority/source/version checks, unique provider linkage, whole saved-record reconciliation and one transactional gift/history/audit commit. Two competing SQLite writers cannot create two gifts.

Known signed charge.refunded and charge.dispute.created events preserve review evidence and close the intent for further posting. They do not automatically void the original gift or execute a refund. After verification, a fresh refunded/disputed provider read denies recording. After recording, review history and the unchanged native gift remain visible; financial resolution requires an adopted policy and separately implemented provider actions.

## Configuration and tenant boundary

Default is Disabled. TEST_ONLY is forbidden with NODE_ENV=production. A selected existing native workspace UUID is required; legacy workspace and every other tenant stay disabled. Operator-only variables: HOSTED_GIVING_MODE=TEST_ONLY, HOSTED_GIVING_TENANT_ID, STRIPE_TEST_SECRET_KEY, STRIPE_TEST_WEBHOOK_SECRET and HOSTED_GIVING_ORIGIN (exact HTTPS origin). No defaults, real keys, live account or bank connection are included.

The platform receives POST /api/hosted-giving/webhook/:tenantId before its ordinary JSON parser. It dispatches the original bounded bytes to the existing active tenant independently of workspace cookies. Unknown, suspended or missing-storage tenants are not provisioned and return retryable refusal. Browser-origin callbacks are refused. The native child verifies the official signature, event identity, test mode and retained binding; the unscoped platform callback is refused. All preparation, detail, verification, retry and gift-recording endpoints require a fresh current administrator/session/MFA and CSRF for writes. Helpers, staff and viewers are denied.

## Reporting, custody and limits

Three administrator-only curated sources distinguish prepared intent amounts, signed provider history and current compatible native recordedCashCents. Repeated historical references are not additional revenue. Current native gift drill-through preserves the actual donor, allocations, payment method and original gift history. Private saved/scheduled execution and retained delivery remain denied after owner downgrade. Raw payloads, signatures, checkout URLs, request/idempotency bindings and credentials are excluded from report fields.

Five ledgers retain intents, exact request custody, safe signed events, reasoned history and original native gift linkage. Original sources, verified facts and history have immutable application guards. Encrypted authenticated NEW-path recovery preserves them, clears sessions and changes recovery authority so old pending work cannot reactivate. Exact already-retained provider-event replay may be acknowledged without financial or authority effects. Workspace recovery excludes provider keys and platform custody; operating off-host backups, key ownership and full deployment recovery remain open.

Bounds: USD 100–100,000,000 cents per reviewed intent; 1,000 retained intents per workspace; at most 100 intents/history rows per page; raw JSON at most 256 KiB; official client timeout 15 seconds and one network retry; conservative 20-hour explicit checkout retry. No worker autonomously charges or polls. These are implementation bounds, not accepted buyer volume or operational availability.
