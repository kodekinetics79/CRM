## Technical and institutional launch blockers

1. **Hosted core:** current business storage is SQLite through Node/Express, with local isolated tenant/platform additions implemented. Prior live register reports Vercel API routing failure, a Render free/no-disk service and Neon without CRM tables; these are prior observations, not a fresh live inspection here. A corrected configuration or health response does not demonstrate durable CRM. Verify actual API routing, TLS/proxy/session/CSRF, persistence across restart/deploy, country-approved stored copies and recovery.
2. **Identity and read/export scope:** existing admin/staff/viewer mutation controls, versioned role/suspension, session revocation and final-administrator protection are real. Authenticated tenant roles still receive all business collections. Define JEF/helper responsibilities and enforce agreed role/module/field/export permissions; test denied privilege access for helper roles. Q&A54 says school-level reporting restrictions are not needed because users are JEF personnel, so do not mark school-row scoping as a mandatory bidder gap. Optional own-account workspace MFA enrollment/challenge/recovery is implemented only with a protected valid server MFA_ENCRYPTION_KEY; missing/wrong keys fail closed for enabled accounts. Production custody/adopted enrollment or privileged enforcement, preferred SSO and platform-master MFA remain open.
3. **Security assurance:** application password/session hashing and HTTPS controls do not prove encrypted hosted disks or adopted key custody. Manual AES-256-GCM full-workspace backup and verified offline NEW-path restore now exist, including document bytes and enabled MFA with its separate retained key; ordinary JSON export is not this restore path. Prove encrypted hosted storage, platform/key recovery, scheduled backup/approved recovery objectives, protected audit/export events, retention/disposal, monitored response and buyer-acceptable assurance/PCI/privacy scope. Q&A56 accepts equivalent controls and does not require an independent pentest or proposal questionnaire; preferred PCI AoC can follow later. Provide truthful equivalent-control evidence and any requested precontract SDPC ExhibitG, not an invented mandatory certificate/test gate. No product SOC2/ISO or FERPA certification is inferred from host evidence or owner tests.
4. **Current-release proof:** 0.5.0 passed 325/325 tests, zero failures/skips, and a production build after independent fixes. Buyer/cloud acceptance remains open. Require current deployed source, meaningful real-source journeys, isolation/permission/failure/recovery evidence and a clean package supporting the exact shipped claims. See [CURRENT-RELEASE-EVIDENCE.md](CURRENT-RELEASE-EVIDENCE.md); historical test counts cannot establish changed-architecture acceptance.

React/Vite, Next.js, Express, ASP.NET Core and PostgreSQL are implementation choices rather than mandated RFP technologies. The proposed ASP.NET/PostgreSQL migration is not baseline fulfillment or a required detour before protecting conversion/reporting. Any architecture change must preserve integer-cent allocations, commitments versus receipts, void/ledger history, optimistic versions, volunteer capacity/time and audit provenance. Choose and execute the durable architecture with acceptance evidence; do not count a recommendation as deployment.
