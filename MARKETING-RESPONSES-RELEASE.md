## Connected behavior

An administrator selects an existing native constituent and reviews the current primary email, configured audience and exact derived provider lookup identity. A read-only provider retrieval must agree with that source; duplicate native primary emails, merged/secondary/name-only/stale identities fail. Retained provider callback identity is separate from the canonical API subscriber hash. Original source/configuration and provider observations are retained with native UTC observation timestamps; timezone-free callback fired_at is kept separately as unspecified rather than invented UTC.

Provider subscription status is observed evidence rather than a newly granted consent. Marketing eligibility also requires compatible native email preference and no retained purpose-specific suppression. Signed unsubscribe/cleaned/removal evidence is deny-only and survives stale subscribed reads. It does not change all-channel native preference, block printed acknowledgment preparation, execute provider deletion or erase donor financial history. Retiring a connection cannot become a silent resubscription path. No Send, autoSubscribe, provider-write, SMS or suppression-clear action is provided.

Existing provider campaign reports retain bounded sent/bounce/unsubscribe/unique-open/unique-click snapshots. Exact repeat reads do not add the same totals again. Changed observations replace/version the current campaign projection with retained history; aggregate opens/clicks are not proven human replies, per-recipient delivery or income. No CRM message is sent by observing a provider report.

## Controls and boundaries

Internal TEST_ONLY READ_ONLY mode is explicit, selected to one existing native workspace and rejected in production; default is Disabled. This is an internal development restriction, not a claim that Mailchimp offers a Stripe-style sandbox/test-key mode. The official endpoint adapter uses fixed HTTPS server-prefix endpoints, GET only, no redirects or caller URLs, bounded response bytes and a15-second timeout. No provider registration, real account or external credential is included in evidence.

Preparation and observation use reviewed request UUIDs, reasons/current source versions, fresh account/session/MFA/tenant/config checks after external awaits, whole saved-row/source reconciliation and transactional history/audit. Signed callbacks arrive before JSON parsing through the existing-active-tenant platform endpoint, independent of workspace cookies. The native service verifies untouched bounded form-urlencoded bytes with current HMAC timestamp/signature before parsing, refuses duplicate/foreign fields and exact audience/member mismatch, and retains replay evidence without repeated effects.

Three curated administrator-only reporting sources exclude email addresses, member/list/security bindings, raw callbacks, signatures and credentials. Saved/scheduled/retained report access rechecks current authority. Current native constituent drill-through is a source reference, not duplicated recipients. Installed original source/status/suppression/report ledgers need category/hold-aware access/correction/retention/exit/disposal and restored-backup anti-reappearance treatment; immutable history does not implement lawful erasure.
